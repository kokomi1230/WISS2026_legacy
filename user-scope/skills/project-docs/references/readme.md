# README.md の書き方

**読者は人間である。** Claude への指示は `CLAUDE.md` が持つ。両方に同じ内容を書かない。

## 節の順序

standard-readme の必須節を順に置く。逆ピラミッド、つまり最も重要な情報を先頭に置き、後の節ほど読者が絞られる構成にする。

| 順 | 節 | 規則 |
|---|---|---|
| 1 | タイトル | H1。リポジトリ名と一致させる |
| 2 | 説明 | **120 字未満**。`>` で始めない。何であって何のためかを 1 文で |
| 3 | 目次 | README が 100 行を超えるときだけ置く |
| 4 | セットアップ | 導入手順をコードブロックで。依存があれば併記 |
| 5 | 使い方 | 代表的な使い方をコードブロックで |
| 6 | 貢献 | 質問先、PR を受けるか、規約 |
| 7 | ライセンス | SPDX の正式名称と権利者。**最後に置く** |

任意で置けるもの: バナー / バッジ（見出しを付けない）、背景（動機・経緯）、API、メンテナ、謝辞。

## 書き方

- **セットアップと使い方はコピー & ペーストで動くコマンドにする。** 擬似コードや省略形を書かない
- ディレクトリ構成は表か箇条書きで。全ファイルを列挙せず、読み手が迷う階層だけ示す
- 図やスクリーンショットは効果的だが入れすぎない
- 詳細は別ファイルへリンクする。README を長くしない
- 開発規約は書かず、`CLAUDE.md` と `.claude/rules/` へリンクする

## 憶測で埋めない

確認できていない項目は `TODO:` を残す。**それらしい手順を書くと、読んだ人も Claude も実行して失敗する。** 空欄より有害である。

```markdown
## 使い方

TODO: 実験の実行手順（被験者フロー・記録するデータ・解析方法）を追記する。
```

## 存在しないファイルへリンクしない

リンク切れは検査で major として出る。特に次の場面で起きやすい。

- ドキュメントを別の場所へ移した後
- テンプレートから派生したプロジェクトで、テンプレート専用の資料が削除された後

移動先が別リポジトリや外部ミラーで相対リンクが張れない場合は、**Markdown リンクにせずインラインコードでパスを書く**。

````markdown
# <プロジェクト名>

<120 字未満の説明>

## セットアップ

```

## 使い方

```bash
<実際に動く実行コマンド>
```
````
