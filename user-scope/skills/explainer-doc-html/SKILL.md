# 解説資料 HTML 変換 (explainer-doc-html)

HTML の解説資料を、既存資料と揃った落ち着いたデザインで作るための skill。テンプレートと部品は `assets/` に同梱してある。

- `assets/template.html` — 骨組み。複製して中身を差し替える
- `assets/design-guide.md` — デザインの根拠と原則（色の役割・タイポ・レイアウト・対話部品・チェックリスト）

**この 2 ファイルが原本である。** 他の場所にコピーを置いて「原本」と呼ばない。skill 本体と同じ場所に置くことで、どのプロジェクトから発火しても同じテンプレートが確実に見つかる。プロジェクト配下（`docs/` など）に置くと、そのディレクトリを持たないプロジェクトで参照が壊れる。

テンプレート自体を改訂するときは、本 skill の原本（テンプレートリポジトリの `user-scope/skills/explainer-doc-html/assets/`）を直接編集し、`setup-user-scope.sh` で配置し直す。手元の作業用コピーを編集しても skill には反映されない。

## いつ発火させるか

- 「HTML にして」「html で出力」「html 化」「md を html に変換」
- 「解説資料を作って」「資料化して」「まとめ資料にして」
- 調査結果・技術解説・機能紹介を人に見せる形で出力する要求

## 出力先

**解説資料の HTML は `~/.notion-mirror/_html/` にだけ置く。** プロジェクトの `docs/` へ HTML を作らない。同じ資料が複数のリポジトリに散らばって、どれが最新か分からなくなるため（実際に `BrainProducts.html` が 5 箇所に重複した）。

```
~/.notion-mirror/_md/<project>/docs/<name>.md      ← 原文（唯一の原本）
~/.notion-mirror/_html/<DB>/<kind>/<name>.html     ← 清書版（唯一の HTML）
```

- 変換元の Markdown が `_md/` にあるなら、対応する `_html/` のパスへ出す
- Notion の研究ノートに対応する資料は、ミラーの相対パスを写す（例: `_html/研究ノート_DB/知見/BrainProducts.html`）
- Notion 側はページ内で HTML を描画できないため、ノートの冒頭 callout にこのパスを 1 行書いて対応づける

詳細は `notion-knowledge-base` skill の `reference.md`「解説資料の置き場所」を参照。

## 手順

1. `assets/template.html` を読み、複製して作業を始める
2. 内容を 3〜6 個のセクションに割る。各セクションの「一番言いたいこと」を 1 文で決める（1 セクション＝1 メッセージ）
3. 下の対応表に従って本文を部品へ割り当てる
4. 目次と `section` の `id` を揃える。部制なら目次も部で分ける
5. 最後にチェックリストを 1 項目ずつ確認する

## 内容 → 部品の対応表

**Markdown をタグに機械変換しない。** 内容が読み手にとって何なのかを判断して部品を選ぶ。ここがこの skill の中心。

| 元の内容 | 使う部品 |
|---|---|
| 資料タイトルとリード文 | masthead の `.kicker`（カテゴリ）/ `h1` / リード段落 |
| 大見出し（`##` 相当） | `section` + `.secnum` + `h2` + `.h2rule` の型を反復する |
| その節で一番言いたいこと | `.lead`（節の冒頭に置く） |
| 小見出し（`###` 相当） | `h3` |
| 第1部・第2部などの部 | 目次を `details.toc-part` で部ごとに束ね、本文はその部の先頭に `.partmark`（中扉） |
| 表 | `.tablewrap` > `table`。1 列目の項目名は `.rowhead` |
| 箇条書き | `ul.clean`。注意すべき項目だけ `li.warn` |
| 覚えてほしい核心・結論 | `.note`（ラベル「要点」） |
| 禁止・リスク・例外・非対応・失敗しやすい点 | `.caution`（ラベル「注意」） |
| 緊急度のない付加情報・背景 | `.info`（ラベル「補足」） |
| 用語や概念の定義 | `.def`（中に `h3` と説明） |
| A → B → C の流れ・処理経路 | `.flow` / `.node` / `.sep`。`.node small` に補足を入れられる |
| 想定問答・FAQ・「よくある疑問」 | `details` / `summary` / `.qbody`（開閉式） |
| 参考リンク集 | `.doclist` / `.grp`（グループ見出し）/ `a > .u`（URL や補足） |
| コード片・パス・コマンド | `code` |

## 対話部品（積極的に使う。ただし条件付き）

**静的に並べると読み取りにくい情報には、迷わず対話部品を使う。** 逆に条件を満たさないところへ足すと、操作しないと読めない資料になる。すべて opt-in なので、クラスや属性を外せば静的に戻る。スクリプトはテンプレート末尾の 1 ブロックが担うので、部品を足すのに JS を書かない。

| 元の内容 | 使う部品 | 条件 |
|---|---|---|
| 比較の列が 3 つ以上ある表 | `<table class="sortable">` | 読み手が列ごとに「どれが一番か」を知りたいとき |
| 行が 8 を超える一覧表 | `<div class="tablewrap" data-collapse="8">` | 全部見せると前後の文脈が押し流されるとき |
| 環境別・言語別・Before/After の手順 | `.tabs` / `.tablist` / `.panel` | 相互排他で、読み手は普通どれか 1 つしか要らないとき |
| ノードが 3 つ以上あるフロー | `<div class="flow" data-steps>` | 段を追って理解させたいとき |
| 第1部・第2部で構成する資料 | `details.toc-part` + `.part-progress` | 部という最上位の構造を目次に出したいとき |

タブの各 `.panel` には `data-label` を入れる。JS が動かない環境ではこれが小見出しになり、全パネルが縦に並ぶ。

## 色の役割（厳守）

3 つの意味にだけ色を使う。迷ったら「この色は何の役割か」を自問する。

| 色 | 役割 |
|---|---|
| ティール（`--teal`） | 構造と要点。見出し・セクション番号・罫線・リンク・目次・通常のドット・`.note` |
| オーカー（`--ochre`） | 注意・禁止・非対応。`.caution` と `li.warn` |
| グレー（`--info`） | 中立の補足。`.info` |

要点なのにオーカー、注意なのにティール、のように役割と色を食い違わせない。「なんとなく目立たせたい」で色を足さない。強調は `<strong>` か 3 コールアウトで表現する。

**これは作り手の内部規約であり、読み手に見せない。** ヘッダーに色の凡例を出さない（かつて常設していたが、読み手が必要としない制作上の決めごとなので廃止した）。

色調そのものを変えたい場合は `:root` のカラートークンだけを差し替え、役割の対応は保つ。

## 守ること

- 目次 `#toc` の各 `href` と、対応する `section` の `id` を一致させる（`#s1` ↔ `id="s1"`）。ずれると追従ハイライトが効かない
- 部制の資料は目次も部で分ける。通し番号だけのフラットな一覧にしない
- `footer` に出典と作成日（または参照日）を書く
- テンプレートに定義されていない class を新設しない。必要なら既存部品の組み合わせで表現する
- 1 セクション内の情報のかたまりは 3〜5 個以内に抑える

## 避けること

デザインガイドの言う「AI っぽさ」を排除する。

- 絵文字
- 紫のグラデーション
- 過剰な影
- 角丸カードの多用
- 下線や全角大文字による強調
- **色の凡例をヘッダーに出す**
- **検索窓・絞り込み UI を付ける。** 資料は読み物であり探す道具ではない。探す機能は目次と部の構造、それにブラウザの `Ctrl+F` が担う。対話部品を足す方針と混同しない

紙のような背景・強い文字階層・横罫のみの表で「資料」として読ませる。

## 仕上げチェックリスト

- 各セクションの言いたいことが `.lead` に 1 文で書けているか
- 色は 3 役割どおりか。それ以外に色を足していないか
- 目次の `href` と `section` の `id` が全て一致しているか
- 部制なら目次が部で分かれているか
- 対話部品は上記の条件を満たす場所にだけ入っているか
- JS を切っても内容が全部読めるか（タブが縦に並び、折りたたみが開き、フローが全段見える）
- 検索窓を足していないか
- 見出しと本文のサイズ差がはっきりしているか
- 表は横罫のみで、左端が揃っているか
- 絵文字・グラデーション・過剰な影を使っていないか
- 出力先は `~/.notion-mirror/_html/` 配下か（プロジェクトの `docs/` へ書いていないか）
- `footer` に出典と作成日を入れたか
