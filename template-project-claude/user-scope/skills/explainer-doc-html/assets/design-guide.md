# 解説資料テンプレート ― デザインガイド

講義資料・技術解説資料を、統一感のある落ち着いたデザインで量産するためのテンプレートと使い方。
同じディレクトリの `template.html` とセットで使う。デザイン原則（近接・整列・反復・コントラスト／色は絞る／色に役割を持たせる）に基づいて設計している。

---

## 1. このテンプレートの思想

- **1セクション＝1メッセージ。** 各セクションの冒頭（`.lead`）に「一番言いたいこと」を1〜2文で置く。
- **反復で一体感。** 全セクションを「SECTIONラベル → 見出し → 罫線 → 本文」の同じ型で繰り返す。フォーマットを崩さないことがプロっぽさの源。
- **色は絞り、役割で使う。** 装飾のために色を足さない。色を変えるときは必ず下記の役割に沿う。
- **AIっぽさを避ける。** 紫グラデ・過剰な影・絵文字・角丸だらけのカードを使わない。紙のような背景＋強い文字階層＋横罫のみの表で「資料」として読ませる。
- **動きは理解のためだけに足す。** 対話部品は「静的に並べると読み取りにくいもの」に限って使う。操作しないと読めない資料にはしない。

---

## 2. 色の役割（最重要ルール）

色は3つの意味にだけ使う。**この対応を崩さないこと。** 迷ったら「この色は何の役割か？」を自問する。

| 色 | トークン | 役割 | 使う場所 |
|---|---|---|---|
| **ティール（primary）** | `--teal` / `--teal-deep` / `--teal-tint` | 構造と要点 | 見出し・セクション番号・罫線・リンク・目次・箇条書きの通常ドット・`.note`（要点） |
| **オーカー（accent）** | `--ochre` / `--ochre-tint` | 注意・禁止・非対応 | `.caution`（注意）・`li.warn` の項目・リスクや例外の強調 |
| **グレー（neutral）** | `--info` / `--info-tint` | 中立の補足 | `.info`（補足）＝緊急度のない付加情報 |
| 地の文 | `--ink` / `--sub` | 意味を持たない本文 | 通常テキスト・補助テキスト |

> **これは作り手の内部規約であり、読み手に見せるものではない。** 以前はヘッダーに色の凡例を常設していたが、読み手が必要としない制作上の決めごとを資料の一等地に置くことになるため廃止した。色の意味はコールアウトのラベル（要点／注意／補足）が担う。

**やってはいけないこと**
- 要点なのにオーカー、注意なのにティール、のように役割と色を食い違わせる。
- 「なんとなく目立たせたい」で色を足す。強調は原則 `<strong>`（太字）か、既定の3コールアウトで表現する。

### 色を変えたいとき
`:root` のカラートークンだけ変更すれば全体の色調が一括で変わる。役割の対応（teal=要点、ochre=注意、gray=補足）は保ったまま、色相だけ差し替えるのが安全。例：ティールを濃紺に変えるなら `--teal` 系3つを差し替える。

## 3. タイポグラフィ

- 欧文 **Inter** ＋ 和文 **Noto Sans JP** の混植（画面・投影で読みやすいサンセリフ）。Google Fonts から読み込み。
- サイズ階層は4段：**タイトル（1.8rem）／見出しh2（1.42rem）／小見出しh3（1.04rem）／本文（1rem）**。見出しと本文のサイズ差をはっきりつける（中途半端にしない）。
- 強調は「太字」または「色（役割に沿って）」。下線・全角大文字の多用はしない。
- オフライン配布が多い場合は、`<link>` のフォント読み込みを外し、`font-family` をシステムフォントだけにしてもよい。

---

## 4. レイアウト

- 本文カラムは最大 `--maxcol`（780px）。左揃え・グリッド整列で、見出し・本文・表の左端を全セクションで一致させる。
- 左に**スティッキー目次**（スクロール追従で現在位置をハイライト）。820px以下では目次は非表示になり本文が1カラムに。
- セクション間は余白でグループ化（近接）。1セクション内の情報のかたまりは3〜5個以内を目安に。

### 部制の資料

第1部・第2部…で構成する資料では、**目次も部で分ける。** 通し番号だけのフラットな一覧にすると、部という最上位の構造が目次から消えてしまう。

- 目次を `<ol id="toc">` から `<nav id="toc">` ＋ `details.toc-part` に置き換え、部ごとに節をまとめる
- 各部の `summary` に `.part-progress` を置くと、その部の何節まで読んだかが `2/5` の形で出る（スクリプトが自動更新）
- 現在位置のある部は自動で開き、他の部は畳んだままにできる
- 本文側では、その部の最初の `section` の直前に `.partmark`（中扉）を置いて切れ目を示す

部が無い資料はフラットな `<ol id="toc">` のままでよい。スクリプトはどちらの形でも動く。

## 5. 使えるコンポーネント（HTML内のコメント参照）

| コンポーネント | クラス | 用途 |
|---|---|---|
| セクション | `section` + `.secnum` + `h2` + `.h2rule` | 全セクション共通の型。コピーして増やす |
| リード文 | `.lead` | セクション冒頭の1メッセージ |
| 部の中扉 | `.partmark` | 部制のときの部の切れ目 |
| フロー図 | `.flow` / `.node` / `.sep` | 処理・モノの流れ |
| 表 | `.tablewrap` > `table` | 横罫のみ。1列目は `.rowhead` |
| 箇条書き | `ul.clean` / `li` / `li.warn` | 通常＝tealドット、注意＝ochreドット |
| 要点 | `.note`（ラベル「要点」） | 覚えてほしい核心。**teal** |
| 注意 | `.caution`（ラベル「注意」） | 禁止・リスク・例外。**ochre** |
| 補足 | `.info`（ラベル「補足」） | 緊急度のない付加情報。**gray** |
| 定義ブロック | `.def` | 用語・概念の説明 |
| Q&A | `details` / `summary` / `.qbody` | 開閉式の想定問答 |
| リンク集 | `.doclist` / `.grp` | 参考リンク（グループ見出し付き） |

## 6. 対話部品（4種）

**静的に並べると読み取りにくい情報に限って使う。** 条件を満たさないなら静的なままにする。すべて opt-in なので、クラスや属性を外せば元の静的な部品に戻る。

| 部品 | 書き方 | 使う条件 |
|---|---|---|
| 列ソート | `<table class="sortable">` | 比較の列が3つ以上あり、読み手が「どれが一番か」を列ごとに知りたい表 |
| 行折りたたみ | `<div class="tablewrap" data-collapse="8">` | 行が8を超え、全部見せると前後の文脈が押し流される表。上位N行だけ先に見せる |
| タブ切替 | `.tabs` > `.tablist`（`role="tablist"`）+ `.panel`（`role="tabpanel"`） | 同じ主題の相互排他なバリアント（環境別・言語別・Before/After）。読み手は普通どれか1つしか要らない |
| 段階表示 | `<div class="flow" data-steps>` | ノードが3つ以上あるフロー。1段ずつ辿らせ、先の段は薄く落として見せる |

**書くときの決まり**

- タブの各 `.panel` には `data-label` を入れる。JS が動かないときはこれが小見出しとして出て、全パネルが縦に並ぶ
- ソートと折りたたみは併用できる（並べ替えても折りたたみの表示位置は付け直される）
- 段階表示はレイアウトを動かさない。先の段は消さずに薄くするだけにしてある
- 部品を足すのにスクリプトを書かない。テンプレート末尾の1ブロックが全部を担っており、必要なのはクラスと属性だけ

### 検索窓・絞り込みUIは付けない

**資料は読み物であり、探す道具ではない。** 探す機能は目次と部の構造、それにブラウザの `Ctrl+F` が担う。独自の検索欄はヘッダーを圧迫するわりに全文検索としては貧弱で、印刷にも残り、資料を「アプリ」に見せてしまう。対話部品を足す方針とは別のものなので混同しない。

## 7. 新しい資料の作り方（手順）

1. `template.html` を複製し、内容に合った名前で保存。
2. `<title>`・masthead の `.kicker`・`h1`・リード文（`【】`部分）を書き換える。
3. 目次 `#toc` の項目と、各 `section` の `id`・`href` を一致させる（例：`#s1` ↔ `id="s1"`）。部制なら `details.toc-part` の形にする。
4. 各セクションを「型」に沿って埋める。まず `.lead` に1メッセージ、次に本文・表・図。
5. 強調は3コールアウトで。**色の役割を必ず守る**（要点=teal / 注意=ochre / 補足=gray）。
6. 対話部品は第6節の条件を満たすところにだけ入れる。
7. 最後に `footer` へ出典・作成日を記入。

## 8. 仕上げチェックリスト

- [ ] 各セクションの「言いたいこと」が `.lead` に1行で書けているか
- [ ] 色は3役割どおりに使えているか（要点=teal／注意=ochre／補足=gray／それ以外に色を足していないか）
- [ ] 目次の `href` と section の `id` が一致し、追従ハイライトが効くか
- [ ] 部制なら目次が部で分かれているか（フラットな通し番号のままになっていないか）
- [ ] 対話部品は第6節の条件を満たす場所にだけ入っているか
- [ ] JS を切っても内容が全部読めるか（タブが縦に並び、折りたたみが開き、フローが全段見える）
- [ ] 検索窓・絞り込みUIを足していないか
- [ ] 見出しと本文のサイズ差がはっきりしているか
- [ ] 表は横罫のみ・左端が揃っているか
- [ ] 絵文字・グラデ・過剰な影を使っていないか（AIっぽさの排除）
- [ ] 出典・作成日を `footer` に入れたか
