# 日本語文章執筆スタイル (japanese-writing-style)

このスキルは日本語の論文・申請書・学位論文・技術文書を執筆 / 編集する際の、文体・構造・表記の **強制適用ルール** を提供する。本多勝一『日本語の作文技術』および木下是雄『理科系の作文技術』を出典に、研究室で運用されている知見を体系化したもの。原典の完全版は `docs/JAPANESE_WRITING_GUIDE.md` に保存されている（10 章・NG/OK 例集・クイックチェックリストを含む）。

## いつ発火させるか

ユーザーが以下のいずれかに該当する作業を始めたとき、このスキルを自動適用する:

- 日本語論文（学会発表 / ジャーナル投稿）の執筆 / 改稿
- 科研費・JST・財団系などの研究費申請書執筆
- 修論 / 博論 / 卒論の執筆
- 技術ブログ / 書籍 / 仕様書を日本語で書くとき
- 既存の日本語文書を校正するとき
- ユーザーが「である調で書いて」「論文用に整えて」「日本語の文章を直して」と明示したとき

## 基本理念

### 文を書くとき
**短くはっきり言い切る．** わかりやすい文とは、意味がただ一通りに解釈でき、読み返さなくても理解できる文である。

- 修飾語と被修飾語は近くに置く
- 長い修飾語ほど先に、短いほど後に置く
- 読点は思想の最小単位を示すために最小限だけ打つ
- 能動態を中心に書く
- 主語と動詞を正しく対応させる

### 文章を組み立てるとき
**必要最低限の文で話の筋道を立てる．**

- 書き始める前にアウトラインを作る
- 1 段落 1 主題を厳守する
- パラグラフはトピックセンテンスで始める
- 接続詞と語順で論理の筋道をつなぐ

## 句読点（最重要）

- **読点**: 「，」（全角カンマ）を使用。「、」は使用しない
- **句点**: 「．」（全角ピリオド）を使用。「。」は使用しない
- 半角のピリオド・カンマを使う場合は、直後に半角スペースを入れる（詰まり防止）

句読点が「、」「。」のテキストを編集する場合は、まず `/swap-punctuation --to=academic <file>` で一括変換するとよい。コードブロック / LaTeX 数式 / URL は自動で保護される。

読点は以下の 2 つの場合にのみ打つ:

1. **短い修飾語を前に置くとき**
   - 例: 「Aが，私が震えるほど大好きなBを私の親友のCに紹介した．」
2. **2 つの節をつなげるとき**
   - 例: 「中野に雨が降り始めたとき，私はすでに駅についていた．」

2 つ以上の長い修飾節を 1 つの名詞につなげると「逆茂木型」となり読みづらい。文を分割するか、被修飾語を前に出すこと。

## 文体

- **である調** を一貫して使用（「です・ます調」と混在させない）
- 大学院生レベルの学術的な文体
- 客観的で検証可能な記述

## 修飾の順序

以下の 4 つの視点で順序を決める:

1. **節を先にし、句を後にする**
   - 節: 動詞を含むことばのかたまり
   - 句: 動詞を含まないことばのかたまり
   - 悪い: 速く / ライトを消して / 止まらずに / 走る
   - 良い: ライトを消して / 止まらずに / 速く / 走る
2. **長い修飾語ほど先に、短いほど後に**
3. **大状況・重要内容ほど先に**（概観から細部に）
4. **ことば同士の親和度に注意する**（親和度の強い語が連続すると誤解を招く）

## 能動態中心

日本語の受動態は冗長で曖昧になりやすい。**受動態に出会ったら必ず疑い、書き換えを検討する。**

| 受動態（NG） | 能動態への書き換え（OK） |
| --- | --- |
| Integlass というシステムが提案されている | 尾高らは Integlass というシステムを提案した |
| 提案システムがユーザによってどう使われるか観察する | ユーザが提案システムをどう使うか観察する |
| 散見される | （主語を明確にして書き換える） |
| 行われている | （著者を主語にして能動態に書き換える） |
| 示唆された | 示唆する（分析した本人なので能動で） |

受動態を書きたくなったら、根拠が明確でないか自信がない可能性が高い。書き換えのコツ:

- システム構成 → 自分が構成しているので主語は著者
- 実験結果 → 「グラフ」や「データ」を主語にすれば能動（「示す」「示唆する」）
- 先行研究 → 著者を主語にする
- 考察・結論 → 分析した本人が主語

## 動詞を豊かに使う

文章の柱は動詞である。名詞 +「行う」「することが可能である」と冗長に書くより、動詞そのものを使う。

| 冗長（NG） | 簡潔（OK） |
| --- | --- |
| 両者の計算を同時に行うため，高速に処理することが可能である | 両者を同時に計算するため，高速に処理できる |
| 〜することができる | 〜できる |
| 〜することが多い | 多くの〜が〜する |
| 〜することを確認した | 〜を確認した |

修飾語を磨くなら、**形容詞よりも副詞** を選ぶ。「形容詞 + 名詞 + 行う」より「副詞 + 動詞」が表現として豊かになる。

## 曖昧な動詞を避ける

意味の広い動詞は熟語化する:

| 曖昧 | 言い換え例 |
| --- | --- |
| 知る | 把握する、認識する |
| ある | 存在する、記載されている |
| 見る | 観察する、参照する |
| 聞く | 聴取する、質問する |

## 避けるべき語尾・表現

| 表現 | 問題点 | 対処 |
| --- | --- | --- |
| 考えられる / 考える | 主語が著者になり断言を避けている | 「可能性がある」「示唆する」「見込む」「期待する」「有望である」 |
| ように / ような | 曖昧 | 削除するか具体例を挙げる |
| 〜したり，〜たり | 単独使用は文法的にも誤り | 削除して「，」で済むことが多い。使うなら 2 回以上 |
| っている | 冗長 | 避ける |
| していた / ていた | 時制が曖昧 | 避ける |
| してもらった | 主語が著者になる | 「実験参加者は〜した」と主語を参加者に |
| ことである | 冗長 | 直接動詞にする |
| ことが多い | 「こと」が冗長、「多い」のかかる場所が不明 | 「こと」を削除し、「多い」を直接かかる場所へ |
| ことを確認した | 冗長 | 直接動詞にする |
| とする | 主語が不明 | 主語を明確にして能動で |
| 散見される | 受動態、曖昧 | 主語を立てて能動で |
| 〜と思う | 主観的 | 「〜と考える」「〜が示唆される」 |

## 接続詞

「しかし」は強い接続詞である。本当に前の文章と対立や転換があるかを確認してから使う。論文っぽく見せるための「しかし」は不要。

| 関係 | 代表例 |
| --- | --- |
| 順接 | だから、したがって、それゆえ |
| 逆接 | しかし、ところが、だが |
| 添加 | さらに、加えて、しかも |
| 対比 | 一方、それに対して |
| 例示 | たとえば、具体的には |
| 換言 | すなわち、つまり、言い換えれば |

## 文章の構成

### 文の構造比率（学術文章の目安）

- 複文（従属節を含む）: 約 **70%**（因果・条件・譲歩など）
- 重文（等位接続）: 約 **25%**（対比・並列・補足）
- 単文: 約 **5%**（強調・導入・転換）

### パラグラフ

1 つのパラグラフは 1 つの言いたいことを含む。これを示す文を **トピックセンテンス** と呼ぶ。

パラグラフは以下の要素で構成する:

1. **トピックセンテンス**（段落の主題を端的に示す、**40〜60 文字程度**）
2. **トピックセンテンスを支える文**（具体例・補足・根拠）
3. **次のパラグラフへつなぐ文**（必要に応じて）

段落の長さは **3〜8 文程度（最大 10 文）**。段落間は 1 行空ける。

### 文のつなぎ方

1. **前文に含む情報を文の前に置く** — 前の文で出た要素を次の文の冒頭に置くと、論理がつながる
2. **適切な接続詞を挿入する** — 論理関係に応じた接続詞を選ぶ
3. **逆茂木型の順番にしない** — 並べた事柄の関係がパラグラフ全体を読み終えてはじめてわかる書き方を避ける

## 表記ルール

### 漢字・ひらがなの使い分け（論文内で統一）

| 漢字 | ひらがな | 使い分け |
| --- | --- | --- |
| 出来る | できる | **できる** を使う |
| 時 | とき | 「場合」で置き換えられるなら **とき** |
| 事 | こと | 漠然とした事柄なら **こと**。事件・出来事の意なら **事** |
| 言う | いう | 文脈に応じて統一 |

### 半角・全角

- 英数字は半角
- 数字はアラビア数字（漢数字は使わない）
- 4 桁以上はカンマで区切る（例: 1,000）
- 単位は半角スペースを空けて記載（例: 100 Hz, 10 ms）
- 日本語の括弧は全角（）、英文中の括弧は半角 ()

### カタカナ語の長音

「-or」「-er」「-ar」で終わる単語の長音記号の有無を **論文全体で統一** する。「デザイナ / デザイナー」「ユーザ / ユーザー」「インタフェース / インターフェース」のどちらでも構わないが、**統一が最優先**。

### 「など」の使い方

「など」は最低でも 2 つ以上列挙してから使う。

- 悪い: A など
- 良い: A, B など

### 自作熟語を避ける

「××管理システム」「××感」など、自分で単語を 2 語以上つなげて作った熟語は極力使わない。「の」や「〜を〜する〜」といった助詞を入れて漢字の羅列を回避する。どうしても使うなら、初出より前で定義しておく。

### 専門用語

- 初出時は英語表記を併記する（例: 脳波（Electroencephalography, EEG））
- 2 回目以降は日本語または略語を使う

### 引用・参考文献

- BibTeX の `\cite{キー}` を使用
- 引用は文末（句点の前）に配置
- 複数文献: `\cite{key1,key2,key3}`
- キー命名規則: `著者名_出版年_キーワード`（例: `nam2018brain`）
- **参考文献の表記統一を忘れがちなので注意**

## 論文執筆特有のルール

### 章立て

- 章立ては原則として節まで。1.1.1（項）は作らない
- 「本章では〜」「本節では〜」を適切に使い分ける

### 引用時の人名

- 苗字のみを使う

### 背景・導入

**避けるべきパターン:**

- 「近年〜」「時代が〜」など歴史や時代を理由にする（卒論・修論・博論は別）
- 「ないから提案する」という否定スタートのモチベーション
- 「確立されていない」「普及していない」という雑な反証
- 「既存システムは高額だからダメ」（高額でも売られている事実は技術的価値や量産化の可能性を示しており、反証として弱い）

**正しい流れ:**

- 「先行研究はこれだけある．しかし XXX や XXX という課題がある」と **ポジティブに** 書く
- 「A である．そこで本研究では B する」という流れに飛躍がないか確認する
- 研究の目的は **1 つ** に絞る（問題は複数提示してよい）
- 「目的として」という表現は避け、「本研究の目的は〜である」と書く

### 図表

- 図 1 は論文の概要を一発で示す内容にする
- 図 1 は 1 ページ目右上または概要直下に配置
- キャプションで研究の狙いや効果が伝わるまで具体的に書く
- 図は紙面の上端または下端に寄せる（途中は NG）
- 人物のシルエットはトレースなどでリアルに。棒人間・いらすとや系は NG
- グラフは軸の名前・単位を明確にし、文字サイズが小さすぎないように

### 実験・考察

- 「被験者」ではなく **「参加者」**
- 「参加者に〜してもらう」ではなく **「参加者は〜する」** と主語を参加者にして能動で
- 議論は実験結果を踏まえ、背景と目的の達成度を制約とともに整理する
- 議論を「できない」「わからない」のネガティブで終わらせない。解決の可能性や改善の方向を書く
- 「考えている」「考える」で終わらず、「可能性が上がる」「示唆する」に書き換える

### 参考文献の量（投稿先別の目安）

- フルペーパー: 最低 30 件以上
- デモ: 20 件以上
- CHI フルペーパー: 50〜100 件は普通
- ページ数カウントに含まれるか否かを必ず確認

### ダブルブラインド対応

- 著者や所属が特定できる文章・写真は避ける
- 著者名・所属・メールアドレスのミスを確認

## 申請書執筆特有のルール（grant proposal mode）

> **適用条件**: ユーザーが「科研費」「申請書」「JST」「財団」などを明示した場合。論文と異なるルールセットなので明示判定する。

### 走査読み設計

審査委員は 1 件あたり数分で走査する。以下の設計原則を守る:

- **太字（Markdown: `**キーワード**`、LaTeX: `\textbf{}`）**: 段落内の最重要キーワード・主張を **1〜2 箇所** に限定
- **下線（Markdown: HTML `<u>文</u>`、LaTeX: `\underline{}`）**: サブセクション内の **結論文・インパクト文** に使用
- 太字と下線だけを拾い読みしても申請書全体の主張が伝わる設計にする
- 太字と下線を同一箇所に重複使用しない
- 1 段落あたりの太字箇所は 1〜2 箇所（3 箇所以上は乱用）

### 能動的・断言的な記述

- 「本研究は〇〇を明らかにする」（能動・断言） — 正しい
- 「〇〇が明らかにされる予定である」（受動・曖昧） — 誤り
- 目標・計画は断言する。不確実な成果のみ「〜が期待される」を使う

### 独自性・創造性の明示

- **独自性**: 「なぜこの申請者でなければならないか」（固有データ・独自手法・特異な研究環境・先行業績）
- **創造性**: 「どんな新しい価値を生むか」（新理論・新技術・新応用・パラダイムシフト）
- 独自性と創造性は混同せず、それぞれ **独立した段落** で述べる

### 文の長さ（申請書向け調整）

- 1 文: **40〜60 字** を目安（通常の論文より短く）
- 1 段落: **3〜6 文**（論文の 3〜8 文より短く）
- サブセクション冒頭に **1 文サマリー** を置く

### 図・表のグレースケール対応

- 科研費基盤 B/C・若手研究・挑戦的研究は審査書類がモノクロ印刷される
- グレースケールで情報が失われないよう設計する
- 色で区別する情報は、線種・パターン・形状でも区別できるようにする
- 最終確認は PDF をグレースケール印刷してから行う

### 新規性のフレーミング

**避ける:**

- 「このテーマはまだ研究されていない」（根拠不明・過言の可能性）
- 「手法 A と B を組み合わせる」（手法的新規性のみでは不十分）
- 「〇〇分野に貢献する」（具体的パスウェイがない）

**正しい:**

- 「〇〇が未解明である理由は〜であり、本研究の〜という独自アプローチがこのギャップを埋める」

### 引用（申請書向け）

- 引用は根拠となる先行研究のみに限定（論文より少なめ）
- 重要な **5〜10 件** に絞る
- 引用過多は読みやすさを損なう

- [ ] 「考えている / 考える」を「示唆する / 可能性がある」に書き換えたか
- [ ] 議論が実験結果と目的に対応しているか

### 提出前最終確認

- [ ] 全項目が埋まっているか
- [ ] 参考文献は十分か（フル 30 件以上・デモ 20 件以上が目安）
- [ ] ダブルブラインド対応で著者特定情報を除いたか
- [ ] 著者名・所属・メールアドレスにミスはないか

### 申請書専用

- [ ] 太字・下線だけで主張が読み取れるか
- [ ] 太字は 1 段落あたり 1〜2 箇所に収まっているか
- [ ] 目標・計画は能動・断言で書かれているか
- [ ] 独自性と創造性をそれぞれ独立した段落で述べたか
- [ ] グレースケール印刷で情報が失われないか
- [ ] 新規性が「未解明の理由」と「ギャップを埋めるパス」で示されているか
