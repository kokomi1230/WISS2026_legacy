## 1. 基本理念

### 1.1 文を書くときの基本理念

**短くはっきり言い切る．**

わかりやすい文とは，意味がただ一通りに解釈でき，読み返さなくても理解できる文である．これを実現する原則は以下のとおり．

- 修飾語と被修飾語は近くに置く
- 長い修飾語ほど先に，短いほど後に置く
- 読点は思想の最小単位を示すために最小限だけ打つ
- 能動態を中心に書く
- 主語と動詞を正しく対応させる

### 1.2 文章を組み立てるときの基本理念

**必要最低限の文で話の筋道を立てる．**

- 書き始める前にアウトラインを作る
- 1段落1主題を厳守する
- パラグラフはトピックセンテンスで始める
- 接続詞と語順で論理の筋道をつなぐ

## 2. 文の書き方

### 2.1 修飾・被修飾の位置関係

修飾することばと被修飾のことばは近くに配置する．

> 悪い例：私は金子が八木がマクドナルドにいたと話すのを聞いた．
> 良い例：八木がマクドナルドにいたと金子が話すのを私は聞いた．

### 2.2 修飾の順序

以下の4つの視点で順序を決める．

**(1) 節を先にし，句を後にする**

- 節：動詞を含むことばのかたまり
- 句：動詞を含まないことばのかたまり

> 悪い例：速く / ライトを消して / 止まらずに / 走る
> 良い例：ライトを消して / 止まらずに / 速く / 走る

**(2) 長い修飾語ほど先に，短いほど後に**

> 悪い例：Aが / 私が震えるほど大好きなBを / 私の親友のCに / 紹介した．
> 良い例：私が震えるほど大好きなBを / 私の親友のCに / Aが / 紹介した．

**(3) 大状況・重要内容ほど先に（概観から細部に）**

> 悪い例：小さな点となって / シャボン玉が / 家の上空に / 消えていった．
> 良い例：家の上空に / シャボン玉が / 小さな点となって / 消えていった．

**(4) ことば同士の親和度に注意する**

親和度の強いことばが連続すると誤解を招きやすい．

> 悪い例：初夏のみどりがもえる夕日に照り映えた．
> 良い例：もえる夕日に初夏のみどりが照り映えた．

### 2.3 読点（，）の打ち方

読点は思想の最小単位を示すものであり，原則として以下の2つの場合にのみ打つ．

**(1) 短い修飾語を前に置くとき**

> 例：Aが，私が震えるほど大好きなBを私の親友のCに紹介した．

倒置文や感嘆文にも適用できる．

**(2) 2つの節をつなげるとき**

> 例：中野に雨が降り始めたとき，私はすでに駅についていた．

2つ以上の長い修飾節を1つの名詞につなげると「逆茂木型」となり読みづらい．文を分割するか，被修飾語を前に出すこと．

### 2.4 能動態中心

日本語の受動態は冗長で曖昧になりやすい．**受動態に出会ったら必ず疑い，書き換えを検討する．**

| 受動態 | 能動態への書き換え |
| --- | --- |
| Integlassというシステムが提案されている | 尾高らはInteglassというシステムを提案した |
| 提案システムがユーザによってどう使われるか観察する | ユーザが提案システムをどう使うか観察する |
| 散見される | （主語を明確にして書き換える） |
| 行われている | （著者を主語にして能動態に書き換える） |
| 示唆された | （分析した本人なので「示唆する」と能動で書く） |

**受動態を書きたくなったら，根拠が明確でないか自信がない可能性が高い．**

書き換えのコツ：

- システム構成 → 自分が構成しているので主語は著者
- 実験結果 → 「グラフ」や「データ」を主語にすれば能動になる（「示す」「示唆する」）
- 先行研究 → 著者を主語にする
- 考察・結論 → 分析した本人が主語

### 2.5 主語と動詞の対応

日本語では主語と動詞が離れがちで，対応が破綻しやすい．

> 悪い例：私は，烏龍茶こそがこの世で最高の飲み物である．
> 良い例：私は，烏龍茶こそがこの世で最高の飲み物だと考える．

### 2.6 動詞を豊かに使う

文章の柱は動詞である．名詞 + 「行う」「することが可能である」と冗長に書くより，動詞そのものを使う．

> 悪い例：両者の計算を同時に行うため，高速に処理することが可能である．
> 良い例：両者を同時に計算するため，高速に処理できる．

修飾語を磨くなら，**形容詞よりも副詞**を選ぶ．「形容詞 + 名詞 + 行う」より「副詞 + 動詞」が表現として豊かになる．

### 2.7 曖昧な動詞を避ける

「知る」「ある」「見る」「聞く」など意味の広い動詞は，熟語を使った動詞に言い換える．

| 曖昧 | 言い換え例 |
| --- | --- |
| 知る | 把握する，認識する |
| ある | 存在する，記載されている |
| 見る | 観察する，参照する |
| 聞く | 聴取する，質問する |

### 2.8 避けるべき語尾・表現

| 表現 | 問題点 | 対処 |
| --- | --- | --- |
| 考えられる / 考える | 主語が著者になり断言を避けている | 「可能性がある」「示唆する」「見込む」「期待する」「有望である」など |
| ように / ような | 曖昧 | 削除するか具体例を挙げる |
| 〜したり，〜たり | 単独で使うと文法的にも誤り | 削除して「，」で済むことが多い．使うなら必ず2回以上 |
| っている | 冗長 | 避ける |
| していた / ていた | 時制が曖昧 | 避ける |
| してもらった | 主語が著者になっている | 「実験参加者は〜した」と主語を参加者に |
| ことである | 冗長 | 直接動詞にする |
| ことが多い | 「こと」が冗長，「多い」のかかる場所が不明 | 「こと」を削除し，「多い」を直接かかる場所へ移動 |
| ことを確認した | 冗長 | 直接動詞にする |
| とする | 主語が不明 | 主語を明確にして能動で |
| 散見される | 受動態，曖昧 | 主語を立てて能動で |
| 〜と思う | 主観的 | 「〜と考える」「〜が示唆される」 |

### 2.9 接続詞の使い方

「しかし」は強い接続詞である．本当に前の文章と対立や転換があるかを確認してから使うこと．論文っぽく見せるための「しかし」は不要である．

接続詞の代表例：

- 順接：だから，したがって，それゆえ
- 逆接：しかし，ところが，だが
- 添加：さらに，加えて，しかも
- 対比：一方，それに対して
- 例示：たとえば，具体的には
- 換言：すなわち，つまり，言い換えれば

## 3. 文章の構成

### 3.1 アウトラインを作る

文章を書く上で最も大事なのは**準備**である．アウトラインを作ってから書き始めること．

アウトライン作成のポイント：

- どういう順序で章立てするか
- 各章で具体的に何を述べるか
- 述べるために必要な材料が手元に揃っているか

### 3.2 パラグラフの構成

1つのパラグラフは1つの言いたいことを含む．これを示す文を**トピックセンテンス**と呼ぶ．

パラグラフは以下の要素で構成する．

1. **トピックセンテンス**（段落の主題を端的に示す，40〜60文字程度）
2. **トピックセンテンスを支える文**（具体例・補足・根拠）
3. **次のパラグラフへつなぐ文**（必要に応じて）

段落の長さは3〜8文程度（最大10文）が目安．段落間は1行空ける．

### 3.3 文のつなぎ方

**(1) 前文に含む情報を文の前に置く**

前の文で出た要素を次の文の冒頭に置くと，論理がつながる．

**(2) 適切な接続詞を挿入する**

論理関係に応じた接続詞を選ぶ（節2.9参照）．

**(3) 逆茂木型の順番にしない**

逆茂木型とは「並べた事柄の関係がパラグラフ全体を読み終えてはじめてわかる」ような書き方を指す．無用な文を切り捨て，話の筋道がはっきりするようにする．

### 3.4 文の構造のバランス（学術文章の目安）

- 複文（従属節を含む）：約70%（因果・条件・譲歩など）
- 重文（等位接続）：約25%（対比・並列・補足）
- 単文：約5%（強調・導入・転換）

## 4. 表記ルール

### 4.1 句読点

- 読点：**「，」**（全角カンマ）を使用
- 句点：**「．」**（全角ピリオド）を使用
- 半角のピリオド・カンマを使う場合は，直後に半角スペースを入れる（詰まり防止）

### 4.2 漢字・ひらがなの使い分け

| 漢字 | ひらがな | 使い分け |
| --- | --- | --- |
| 出来る | できる | **できる** を使う |
| 時 | とき | 「場合」で置き換えられるなら **とき** |
| 事 | こと | 漠然とした事柄なら **こと**．事件・出来事の意なら **事** |
| 言う | いう | 文脈に応じて統一 |

**1つの論文の中で統一することが原則．**

### 4.3 半角・全角の統一

- 英数字は半角
- 数字はアラビア数字（漢数字は使わない）
- 4桁以上はカンマで区切る（例：1,000）
- 単位は半角スペースを空けて記載（例：100 Hz，10 ms）
- 日本語の括弧は全角（）．英文中の括弧は半角 ()

### 4.4 カタカナ語の長音

「-or」「-er」「-ar」で終わる単語の長音記号の有無を**論文全体で統一**する．

| 長音なし | 長音あり |
| --- | --- |
| デザイナ | デザイナー |
| ユーザ | ユーザー |
| インタフェース | インターフェース |
| タイポグラフィ | タイポグラフィー |

伸ばさないのが理系的だと考える人もいるが，どちらでも構わない．**統一が最優先**．

### 4.5 「など」の使い方

「など」は最低でも2つ以上列挙してから使う．1つしか挙げないなら「など」を消す．

> 悪い例：Aなど
> 良い例：A，B など

### 4.6 自作熟語を避ける

「××管理システム」「××感」など，自分で単語を2語以上つなげて作った熟語は極力使わない．「の」や「〜を〜する〜」といった助詞を入れて漢字の羅列を回避する．どうしても使うなら，初出より前で定義しておく．

### 4.7 専門用語

- 初出時は英語表記を併記する（例：脳波（Electroencephalography，EEG））
- 2回目以降は日本語または略語を使う

### 4.8 引用・参考文献

- BibTeXの `\cite{キー}` を使用
- 引用は文末（句点の前）に配置
- 複数文献：`\cite{key1,key2,key3}`
- キー命名規則：`著者名_出版年_キーワード`（例：`nam2018brain`）
- **参考文献の表記統一を忘れがちなので注意**

### 4.9 紛らわしい語の区別

- 特長 / 特徴
- 任意：「任意の値を取る」は◯，「任意の感触をデザインする」は△
- 外人 / 外国人：差別表現を避ける

## 5. 論文執筆特有のルール

### 5.1 文体

- **「である」調**を一貫して使用
- 大学院生レベルの学術的な文体
- 客観的で検証可能な記述

### 5.2 章立て

- 章立ては原則として節まで．1.1.1（項）は作らない
- 「本章では〜」「本節では〜」など使い分ける

### 5.3 引用時の人名

人名を引用するときは**苗字**のみを使う．

### 5.4 背景・導入の書き方

**避けるべきパターン：**

- 「近年〜」「時代が〜」など歴史や時代を理由にする（卒論・修論・博論は別）
- 「ないから提案する」という否定スタートのモチベーション
- 「確立されていない」「普及していない」という雑な反証（読者から疑われ，かつ「自分が確立できるのか」という強い主張になってしまう）
- 「既存システムは高額だからダメ」（高額でも売られている事実は技術的価値や量産化の可能性を示しており，反証として弱い）

**正しい流れ：**

- 「先行研究はこれだけある．しかしXXXやXXXという課題がある」と**ポジティブに**書く
- 「Aである．そこで本研究ではBする」という流れに飛躍がないか確認する
- 研究の目的は**1つ**に絞る（問題は複数提示してよい）
- 「目的として」という表現は避け，「本研究の目的は〜である」と書く

### 5.5 図表

- 図1は論文の概要を一発で示す内容にする
- 図1は1ページ目右上または概要直下に配置する
- キャプションで研究の狙いや効果が伝わるまで具体的に書く（システム図のみはNG）
- 図は紙面の上端または下端に寄せる（途中はNG）
- 人物のシルエットはトレースなどでリアルに．棒人間や「いらすとや」はNG
- 原則イラレを使う
- グラフは軸の名前・単位を明確にし，文字サイズが小さすぎないようにする
- システムのキャプチャ画像は見やすく，ノイズがないように

### 5.6 実験・考察

- 「被験者」ではなく **「参加者」**
- 「参加者に〜してもらう」ではなく「参加者は〜する」と主語を参加者にして能動で
- 議論は実験結果を踏まえ，背景と目的の達成度を制約とともに整理する
- 議論を「できない」「わからない」というネガティブで終わらせない．解決の可能性や改善の方向を書く
- 「考えている」「考える」で終わらず，「可能性が上がる」「示唆する」に書き換える

### 5.7 参考文献の量

- フルペーパー：最低30件以上
- デモ：20件以上
- CHIフルペーパー：50〜100件は普通
- ページ数カウントに含まれるか否かを必ず確認

### 5.8 ダブルブラインド対応

- 著者や所属が特定できる文章・写真は避ける
- 著者名・所属・メールアドレスのミスを確認

## 6. 申請書執筆特有のルール

> **適用条件**：科研費等の研究費申請書を執筆する場合．

### 6.1 走査読み設計

審査委員は1件あたり数分で走査する．以下の設計原則を守る．

- **太字**：段落内の最重要キーワード・主張を1〜2箇所に限定
- <u>下線</u>：サブセクション内の結論文・インパクト文に使用
- 太字と下線だけを拾い読みしても申請書全体の主張が伝わる設計にする
- 太字と下線を同一箇所に重複使用しない
- 1段落あたりの太字箇所は1〜2箇所（3箇所以上は乱用）

### 6.2 能動的・断言的な記述

- 「本研究は〇〇を明らかにする」（能動・断言）← 正しい
- 「〇〇が明らかにされる予定である」（受動・曖昧）← 誤り
- 目標・計画は断言する．不確実な成果のみ「〜が期待される」を使う

### 6.3 独自性・創造性の明示

- **独自性**：「なぜこの申請者でなければならないか」（固有データ・独自手法・特異な研究環境・先行業績）
- **創造性**：「どんな新しい価値を生むか」（新理論・新技術・新応用・パラダイムシフト）
- 独自性と創造性は混同せず，それぞれ独立した段落で述べる

### 6.4 文の長さ（申請書向け調整）

- 1文：40〜60字を目安（通常の論文より短く）
- 1段落：3〜6文（論文の3〜8文より短く）
- サブセクション冒頭に1文サマリーを置く

### 6.5 図・表のグレースケール対応

- 科研費基盤B/C・若手研究・挑戦的研究は審査書類がモノクロ印刷される
- グレースケールで情報が失われないよう設計する
- 色で区別する情報は，線種・パターン・形状でも区別できるようにする
- 最終確認はPDFをグレースケール印刷してから行う

### 6.6 新規性のフレーミング

**避けるべき：**

- 「このテーマはまだ研究されていない」（根拠不明・過言の可能性）
- 「手法AとBを組み合わせる」（手法的新規性のみでは不十分）
- 「〇〇分野に貢献する」（具体的パスウェイがない）

**正しい：**

- 「〇〇が未解明である理由は〜であり，本研究の〜という独自アプローチがこのギャップを埋める」

### 6.7 引用（申請書向け）

- 引用は根拠となる先行研究のみに限定（論文より少なめ）
- 重要な5〜10件に絞る
- 引用過多は読みやすさを損なう

- [ ] 「など」は2個以上列挙してから使っているか
- [ ] 1段落1主題を守っているか
- [ ] 各段落にトピックセンテンスがあるか
- [ ] 段落間の論理的つながりがあるか

### 7.3 論文構成

- [ ] タイトルはわかりやすいか
- [ ] 図1は1ページ目右上または概要直下にあるか
- [ ] 図1は研究の概要を一発で示しているか
- [ ] 図1のキャプションが十分に具体的か
- [ ] グラフの軸名・単位は明確で，読める大きさか
- [ ] 図は紙面の上端または下端に寄せているか
- [ ] イラストはトレースなどでリアルか（棒人間・いらすとやはNG）
- [ ] 章立ては節まで（項は作らない）に収まっているか

### 7.4 背景・目的

- [ ] 背景が「近年〜」など時代依存になっていないか
- [ ] 「Aである．そこで本研究ではB」の流れに飛躍はないか
- [ ] 「ないから提案する」になっていないか
- [ ] 「確立されていない」「普及していない」を使っていないか
- [ ] 先行研究を踏まえて課題をポジティブに表現しているか
- [ ] 研究の目的は1つに絞られているか

### 7.5 実験・考察

- [ ] 「被験者」を「参加者」に統一しているか
- [ ] 議論がネガティブで終わっていないか
- [ ] 「考えている／考える」を「示唆する／可能性がある」に書き換えたか
- [ ] 議論が実験結果と目的に対応しているか

### 7.6 提出前最終確認

- [ ] 全項目が埋まっているか
- [ ] 参考文献は十分か（フル30件以上・デモ20件以上が目安）
- [ ] ダブルブラインド対応で著者特定情報を除いたか
- [ ] 著者名・所属・メールアドレスにミスはないか
- [ ] 美しいデモ動画は準備したか（英語キャプション確認済みか）

### 7.7 申請書専用

- [ ] 太字・下線だけで主張が読み取れるか
- [ ] 太字は1段落あたり1〜2箇所に収まっているか
- [ ] 目標・計画は能動・断言で書かれているか
- [ ] 独自性と創造性をそれぞれ独立した段落で述べたか
- [ ] グレースケール印刷で情報が失われないか
- [ ] 新規性が「未解明の理由」と「ギャップを埋めるパス」で示されているか

## 8. NG / OK 例集

### 8.1 受動態 → 能動態

| NG | OK |
| --- | --- |

| 〜が行われている | （主語）は〜を行っている |

### 8.2 冗長表現 → 簡潔表現

| NG | OK |
| --- | --- |
| 両者の計算を同時に行うため，高速に処理することが可能である | 両者を同時に計算するため，高速に処理できる |
| 〜することができる | 〜できる |
| 〜することが多い | 多くの〜が〜する |
| 〜することを確認した | 〜を確認した |

### 8.3 曖昧 → 具体

| NG | OK |
| --- | --- |

| ある | 存在する／記載されている |
| これは重要である | （具体的に何が重要かを明記する） |

### 8.4 背景の書き方

| NG | OK |
| --- | --- |
